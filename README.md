# CITwinkler · ClassIsland 插件
# AI写的别当成最后更改
作者：Fony Yu

为 [ClassIsland](https://classisland.tech/) 提供两个能力：

1. **「闪烁内容」组件**（容器组件）
   - 可以像「分组容器」一样容纳任意子组件；
   - 在子组件**渲染出来的内容字符边缘**绘制描边，并让描边**平滑渐变闪烁**；
   - 可自定义：闪烁循环时间 / 保持描边、描边颜色（支持双色渐变）、描边粗细、描边明暗范围；
   - 可使用 **ClassIsland 现有规则集**限制闪烁条件——只有在规则集满足时才闪烁 / 显示描边。
2. **「闪烁」自动化行动**
   - 可在自动化中通过任意触发器（cron、上课时、收到信号时……）让指定的「闪烁内容」组件闪烁；
   - 可选择全部或部分「闪烁内容」组件作为目标；
   - 可覆盖本次闪烁的时长、次数、颜色、粗细，也可忽略目标组件的规则集限制。

## 安装

### 方式一：使用插件包（推荐）

1. 构建项目后，在输出目录 `bin/Release/net8.0/` 下可找到 `CITwinkler.cipx`；
2. 打开 ClassIsland →【应用设置】→【插件】→【从本地安装】，选择该 `.cipx` 文件；
3. 重启 ClassIsland（或按提示重新加载插件）。

### 方式二：手动放置

把构建输出目录 `bin/Release/net8.0/` 中的全部文件复制到

```
<ClassIsland 数据目录>/Plugins/fonyu.citwinkler/
```

再重启 ClassIsland。

## 使用

### 添加「闪烁内容」组件

1. 进入【应用设置】→【组件】，在组件库中找到「闪烁内容」，拖动到主界面；
2. 把需要闪烁的组件（例如「文本」「时钟」等）拖入「闪烁内容」组件内部；
3. 选中「闪烁内容」组件，在右侧设置中调整描边颜色、粗细、闪烁模式与循环时间。

### 使用规则集限制闪烁

1. 在「闪烁内容」组件设置中开启「启用规则集限制」；
2. 在下方规则集编辑器中添加规则（规则来源与主界面隐藏规则完全一致，例如「当前时间状态」「焦点窗口」等）；
3. 只有规则集满足时组件才会闪烁 / 显示描边；不满足时描边完全隐藏。

### 添加「闪烁」自动化行动

1. 进入【应用设置】→【自动化】，新建或编辑一个自动化流程；
2. 添加行动 → 分组「闪烁内容」→「闪烁」；
3. 在行动设置中选择作用目标（全部 / 勾选指定组件），并按需覆盖闪烁时长、次数、颜色、粗细。

## 说明

- 描边通过在组件内容外围叠加 `DropShadowEffect` 实现，因此「描边粗细」表现为描边向外扩散的范围，数值越大越柔和。
- **本组件的布局与官方「分组容器」逐像素一致**：子组件的位置、所在行的高度、组件上报给 ClassIsland 的期望尺寸
  都与把子组件直接放进「分组容器」时相同，不会挤动同一行里的其它组件。
- 为容纳向外扩散的光晕，描边宿主在左右各预留 10px（纯绘制溢出，不影响布局）。当「描边粗细」调得很大
  （接近上限 20）时，光晕在组件左右两端仍可能被裁掉一小部分。
- 动画以约 20fps 运行，且仅在「循环闪烁」模式或行动触发的闪烁期间才会启动计时器。

## 性能与已知限制

Avalonia 会为带 `Effect` 的元素建立**独立离屏图层**再叠加模糊滤镜，所以「修改一次滤镜属性」的真实代价
= 重新合成整棵子树 + 重新模糊整个图层。本组件为此做了如下约束：

| 措施 | 作用 |
|---|---|
| 描边宿主 `VerticalAlignment="Stretch"` + **不设 `Padding`** | 布局与官方「分组容器」完全一致（子组件位置 / 行高 / 期望尺寸均相同）。**切勿**改回 `Top`（子组件会贴到容器上沿）、`Center`，也**切勿**用 `Padding` 预留光晕空间——那会把组件的期望高度撑大 2×Padding，一旦所在行的高度小于「内容 + Padding」，子组件会被压成 0×0，整个组件变成空白 |
| 描边宿主 `ClipToBounds="True"` | 离屏图层严格限制在组件自身范围内，避免超大离屏缓冲 |
| 宿主左右各外扩 10px（负外边距 + 子组件容器/ presenter 边距抵消） | 为光晕预留绘制空间，同时保证子组件位置与组件期望尺寸不变 |
| 不透明度量化 + 值未变化时跳过 | 大量相邻帧直接跳过，减少重绘次数 |
| 描边不可见（不透明度 ≈ 0）时卸下滤镜 | 暗态期间零渲染开销，不再是"看不到也在算" |
| 仅「渐变描边」且两色不同时才挂第二层滤镜 | 单色 / 同色时渲染成本直接减半 |
| 模糊半径上限 18px | 限制图层膨胀，描边粗细设置上限相应为 20 |
| 运行时面积校验（含尺寸变化时复检） | 宿主渲染面积超过 150 万像素时拒绝挂载滤镜并写一条告警日志，避免生成超大离屏图层 |
| 规则集判定结果缓存 | 不在动画帧里反复求值规则集 |
| 主界面隐藏时暂停刷新 | 最小化 / 未显示时不做无用渲染 |

如需进一步降低占用：把「闪烁模式」改成**保持描边**（描边静态常亮，此时完全不启动动画计时器，无逐帧开销），
或调小「描边粗细」。

## 更新记录

- **1.0.4**
  - 修复：**「启用描边」关闭时子组件贴到容器上沿、开启时组件变成空白。** 两个症状同源，都出在 1.0.1~1.0.3
    描边宿主的对齐方式与 `Padding` 上：
    - 宿主用 `Top` 时尺寸会收缩到内容高度，而官方「分组容器」是 `Stretch`，于是子组件贴到容器上沿；
    - `Padding`（内外两层共约 2×36px）会把组件期望高度撑大近 3 倍。当所在行的可用高度小于「内容 + Padding」时，
      子组件被排成 **0×0**，整个组件渲染为空白（已用离屏渲染实测复现：`lit=0`、`child=0,0 0×0`）。
  - 现改为：宿主 `VerticalAlignment="Stretch"`、**完全取消 `Padding`**、保留 `ClipToBounds="True"`，
    并用「宿主外扩 10px + 子组件容器 / presenter 边距抵消」的方式为光晕预留绘制空间。
    已用 Avalonia 11.3.6 离屏渲染与官方容器结构做逐像素对比：子组件位置、组件期望宽度、多子组件时的间距全部一致。
  - 新增：宿主尺寸变化时重新校验渲染面积（超过 150 万像素即卸下滤镜并记录告警），避免布局异常时生成超大离屏图层。
  - 「渐变描边」在两种颜色相同时自动退化为单层滤镜（省一半渲染成本）。

- **1.0.3**
  - 修复：容器包含子组件后组件在主界面上显示为空白（**真正根因**）。
    1.0.1 重写 `FlashContentComponent.axaml.cs` 时漏掉了构造函数里的 `InitializeComponent()`。
    `ComponentBase` 继承自 `UserControl`，可视树完全依赖该调用把 `FlashContentComponent.axaml` 载入并填充
    `x:Name` 字段；漏掉之后组件**没有任何可视树**，因此表现为一片空白（配置与子组件其实都是正常的）。
    现已补上该调用，并为所有命名控件加上空值保护：可视树缺失时只跳过描边渲染，不再抛异常。
  - 新增诊断日志：组件加载时向 ClassIsland 主日志写入一条 `Information`（子组件数量 / 描边粗细 / 模式）；
    可视树缺失时写入 `Warning`，便于快速定位同类问题。
  - 兜底：配置文件中 `Children` 为 `null` 时自动补一个空集合。

- **1.0.2**
  - 尝试修复「容器包含子组件后显示为空白」，**但未命中根因**（真正原因见 1.0.3）。这次改动是把描边宿主的
    `VerticalAlignment` 由 `Center` 改成 `Top`；该改动在 1.0.4 中已被 `Stretch` 取代。
  - 新增运行时尺寸校验：宿主尺寸异常时拒绝挂载滤镜，避免出现超大离屏图层。

- **1.0.1**
  - 修复：把本组件添加到主界面后 CPU 占用立刻上升 20%+、系统卡顿直至 ClassIsland 闪退。
    根因是同时修改两层嵌套滤镜的不透明度（每秒 30 次），且描边宿主未裁剪，
    `DropShadowEffect` 的离屏图层被放大到整屏 / 无限尺寸，导致持续的超大缓冲区分配。
  - 描边粗细上限由 30 调整为 20（模糊半径已设 18px 上限，更大数值不再有视觉差异）。
